# 接线表

## ESP32-WROOM-32E

| ESP32 引脚 | 连接到 | 说明 |
|---|---|---|
| GPIO21 | OLED SDA | I2C 数据 |
| GPIO22 | OLED SCL | I2C 时钟 |
| 3V3 | OLED VCC | 1.3" OLED 供电（3.3V） |
| GND | OLED GND | 共地 |
| GPIO16 (RX) | 红外模块 TX | ESP32 接收 |
| GPIO17 (TX) | 红外模块 RX | ESP32 发送 |
| 5V/VIN 或 3V3 | 红外模块 VCC | 模块 3.3~5V |
| GND | 红外模块 GND | 共地 |
| GPIO4 | DHT11 DATA | 室温/湿度传感器（见下）|
| 3V3 | DHT11 VCC | DHT11 供电（3.3V）|
| GND | DHT11 GND | 共地 |

红外模块：TTL 串口，115200 8N1，38KHz 载波，遥控距离约 5~8m。

### ⚠️ 供电：模块走独立电源时**必须共地**

上表每一行的「共地」都指 **模块的地要回到 ESP32 的 GND**。当你用**拓展电源板（3.3V/5V）**
给 OLED / 红外 / DHT11 供电、而 **ESP32 自己插在 USB-C** 上时，两套电源各有各的「地」——
**少了那根 GND 连线，两边就没有共同的参考电平**，即使在模块上量得到 3.3V 也照样不通。

症状很有辨识度：**快的总线先死、慢的照活**。

| 模块 | 总线 | 缺共地时的现象 |
|---|---|---|
| OLED | I2C 100 kHz | `[oled] no display answering -> running headless`（一个 ACK 都不给）|
| 红外模块 | UART 115200 | 发得出、收不到，自检 `k` = 0/8 |
| DHT11 | 单总线（毫秒级）| **正常出数** |

> 真机实测（2026-10-15）：补上共地那根线的瞬间，**OLED 和红外同时恢复**；
> 在那之前固件侧一切正常，只有这两条「快」总线像没接一样。

**量法**：万用表黑笔放 **ESP32 的 GND**、红笔放**拓展电源的 GND**，应为 **0 V**。
（黑笔放到模块自己的 GND 上量是错的——地断了也会显示正常 3.3V。）

快速开始见 [README](../README.md)，完整排查故事见 [硬件联调 §2 红外模块](hardware-validation.md)。

## DHT11 室温传感器

用于闭环夜间控制（设计 §6.1）：固件每 `DHT_READ_MS`（30s）读一次，把
`{temp,humidity,ok}` 发到 `<prefix>/env`；**决策在树莓派上做**，固件只负责测量。

### 接线

| DHT11 引脚 | 连接到 | 说明 |
|---|---|---|
| VCC / +(第 1 脚) | 3V3 | 3.3V；模块版多为中间脚 |
| DATA / OUT / S | **GPIO4** | 单总线数据 |
| NC | — | 空脚，不接 |
| GND / -(第 4 脚) | GND | 共地 |

**必须加 4.7kΩ~10kΩ 上拉电阻**：DATA ↔ 3V3。
买带小 PCB 的 DHT11 模块（3 脚：VCC/DATA/GND）的话，板上已经带了这个电阻，
直插即可；裸传感器（4 脚）一定要自己加上拉，否则读数会时好时坏。

- **为什么是 GPIO4**：它没有 strapping / 启动特殊功能，也不是输入专用脚，
  上电瞬间不会把数据线拉到影响启动的电平，是最省心的选择。
- 引脚在 `src/pins.h` 的 `PIN_DHT` 中定义，改一行即可。
- 上电后 1s 内不要读；固件把第一次读取放在启动约 5s 之后。
- 读数失败时固件发 `ok:false`（并打串口日志），服务端会当"没有数据"处理，
  不会拿它去调温度。

> DHT11 精度有限（1℃ 分辨率、±2℃ 误差、±5% RH），所以夜间闭环用了
> ±1℃ 死区 + 最小动作间隔，而不是见差就调（设计 §7.2）。

## 1.3" 4 脚 OLED

4 个引脚依次为 **GND / VCC / SCL / SDA**（不同批次顺序可能不同，以丝印为准）。I2C 地址通常为 `0x3C`，少数为 `0x3D`，固件会在启动时自动探测。

- 默认控制器：**SH1106**（1.3" 常见）。若为 0.96" SSD1306，把 `src/config.h` 里 `OLED_SH1106` 改为 `0`。

## 可选三键导航（已接线，基础按键验收正常）

选择常开、按下接通、松手复位的无灯机械按键，不要自锁型。接线前核对实际板型、丝印、引出和外接占用。2026-10-31 用户确认已按本表接线，三键固件已烧录；随后反馈基础按键与屏幕测试“没问题”。交互见 [运行时约定](runtime.md)，测试范围与记录见 [三键计划](superpowers/plans/2026-10-27-oled-buttons-diagnostics.md#2026-10-31-接线后联调)。

| 按键 | GPIO | 另一端 |
|---|---|---|
| LEFT / ◀ | GPIO25 | ESP32 GND |
| OK | GPIO26 | ESP32 GND |
| RIGHT / ▶ | GPIO27 | ESP32 GND |

- 裸开关接 GPIO 与 GND，不接 VCC；内部上拉、低电平有效。不要把 5V 接入 GPIO。
- 四脚轻触按键可能同组内部常通，先用万用表确认两组触点，勿按外观随意跨接。
- 带 PCB 模块须确认电路为兼容 3.3V 的低有效输出，不只凭名称认定可替代裸开关。不依赖灯、触摸或电阻分压。
- 不复用 GPIO0 BOOT、RST/EN。未接模块时维持自动轮播；线长、噪声、手感与额外滤波需求待实测。

## 引脚可改

全部在 `src/pins.h` 中定义：

```c
#define PIN_OLED_SDA 21
#define PIN_OLED_SCL 22
#define PIN_IR_RX 16
#define PIN_IR_TX 17
```
