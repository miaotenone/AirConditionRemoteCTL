# 运行时约定

本文件描述现有固件，不扩展功能或改变策略。跨仓库细节见 [接口规格 §4](rpi-feishu-interface-spec.md)。

## 命令与影子状态

`<prefix>/cmd` 接受部分字段 `power/mode/temp/fan`，默认前缀 `ac`。温度夹取到 16–30℃，模式 0–4，风速 0–3，电源规范为 0/1。MQTT 回调复制 payload 到单个待处理缓冲，主循环解析 JSON，再执行命令；不是持久消息队列。

- 至少一个字段被识别：更新影子状态 → 保存 NVS → 发完整 `0x30` 红外帧 → 立即回 retained state → 更新显示。**即使字段值与原值相同也执行此路径**；`ac_state_apply_field` 返回的是“识别字段”，不是“数值发生变化”。
- 空对象/全未知字段对象：不写 NVS、不发红外，但立即回 state；未知字段记日志。
- 坏 JSON 或非对象：忽略，不保证状态回执。
- state 是网关记忆，不能证明实体空调执行成功。实体遥控器操作不会回写网关，下一次完整帧可能覆盖实体状态。

## NVS 与启动

配置与影子状态使用 `acctl` 命名空间。影子字段为 `st_power/st_mode/st_temp/st_fan`，以 `st_power` 是否存在判断是否记住过状态；缺失字段沿用调用方初值。

启动先用配置的 initial，再尝试载入已存影子并夹取合法范围。启动不会主动发开机红外。被接受的命令及失联关机保存影子；每 30 秒状态重发不写 NVS。普通刷固件通常保留 NVS，擦除 flash 或恢复出厂不会。

BOOT 长按 3 秒、开机 2 秒窗口内串口 `r`、串口 `reset` 均会清除 WiFi、应用配置及影子状态后重启。不要把恢复出厂当作无损排障命令。

## 联系、关机与恢复

健康联系同时要求 WiFi/MQTT 已连接及服务心跳未超时。设备按 `millis()` 记录 `<prefix>/hb` **到达时间**，不按 payload 的 `ts` 判活。

| 条件 | 行为 |
|---|---|
| 尚未有过健康联系 | 不武装失联关机，避免无网启动误操作空调 |
| 首次健康联系 | 武装保护，每次健康循环刷新最后联系时刻 |
| 已武装，健康联系中断满 300 秒 | 记住关机前影子 → power=0 → 存 NVS → 发一次红外关机 → 尝试发布离线 state → 标记待报事件 |
| 同一次中断持续 | 不重复发关机；保护计时按 32 位无符号差值处理回绕 |
| 联系恢复 | 清除保护触发标记、立即发布 state，尝试补发 `failsafe_off` 事件 |
| 时钟未同步或发布失败 | 待报事件留 RAM，后续健康循环重试 |

WiFi/MQTT 持续断开时，约在最后健康联系后 300 秒关机；仅心跳中断、MQTT 仍在线时，心跳先在 90 秒失效，再计 300 秒，约在最后心跳后 390 秒关机，另有主循环延迟。

事件不 retained，包含 `type/ts/prev`；`ts` 是**实际发布时**生成的 Unix 秒，不是关机发生时刻。固件自身不自动重新开机，服务端根据事件决定是否恢复。此机制尽力而为：网络 watchdog 重启会丢失 RAM 中的待报事件，NVS 中仍是关机影子；恢复消息也没有与用户新命令之间的顺序标识，不能保证最新用户意图优先。

## 网络与配网

网络看门狗观察 WiFi+MQTT，不以服务心跳作为重拨条件。最后网络健康后 15 秒开始强制重拨 WiFi，之后至少间隔 15 秒；10 分钟仍未恢复则重启。阈值及门户配置见 `src/config.h`。

启动优先尝试已存网络 20 秒，失败进入非阻塞门户。无客户端时闲置上限 180 秒；有手机连接会延长闲置时间，但单次门户仍有 900 秒硬上限。串口控制台和 BOOT 在连接、门户及正常运行阶段都可用。**门户位于 setup，期间不执行 main loop 失联保护**；反复连接失败还可能重启后再次进入门户。

## 发布与显示

- state/status/env retained；cmd/hb/event 不 retained。离线 LWT 设 QoS1，其他固件主动 publish 为 QoS0；固件订阅 cmd/hb 为 QoS0。详见接口规格，不应笼统说所有消息 QoS0/1。
- DHT11 首读延后约 5 秒，之后每 30 秒读一次。失败上报 `ok=false`，显示 `NO DATA / CHECK SENSOR`，不把旧值当有效新读数。环境消息无 `ts` 字段。
- OLED 四页 `AIRCON/ROOM/LINK/FIRMWARE`，每 5 秒切页；保留约 240ms 滑动，分页分别裁剪以免相互覆盖。大字号设定/室内温度、反白开机徽标、湿度条和底部分页指示统一布局。
- 页眉在保护触发时优先显示 `SAFE OFF`，否则显示 `SVC OK / NO HB`。这是服务心跳标记，不是 WiFi 信号强度或空调物理执行确认；网络详情仍在 LINK 页。
- 固件页标记 `OLED UI3`，展示 git 短哈希及构建时间，脏树带 `-dirty`。启动/手动页面保留原诊断内容与显示接管行为。
- OTA 默认启用且未设置密码，MQTT 未使用 TLS。仅用于可信隔离网络，见 [安全说明](../SECURITY.md)。

## 三键导航与只读诊断（基础按键验收正常）

可选三键 LEFT / OK / RIGHT 只操作 OLED，不控制空调、不写 NVS、不发送红外，不改变 MQTT 契约、判活与保护策略。未接按键维持自动轮播。技术路线见 [三键计划](superpowers/plans/2026-10-27-oled-buttons-diagnostics.md)。

| 操作 | 概览 | 诊断详情 |
|---|---|---|
| 左/右短按 | 循环切换四页并固定 | 循环切换五项 |
| OK 短按 | 切换自动/固定 | 无操作，保留返回模式 |
| OK 长按 | 进入诊断详情 | 返回原概览页和模式 |

- 页脚显示 AUTO / HOLD / DIAG。固定只停止切页，数据继续更新；恢复自动/退出详情后重计完整 5 秒。按键打断切页动画。
- 去抖 30ms，OK 稳定按下 800ms 长按只触发一次，释放不再短按；左右长持不连发，释放只切一次。初始化持键先释放再按；多键同时按下忽略整次手势，全部松手后恢复。不使用双击或组合快捷键。
- setup 完成后才启用三键，启动/配网/自检手动画面独占屏幕；BOOT 恢复出厂功能不变，不属于导航键。

| 详情 | 含义 |
|---|---|
| NETWORK | WiFi / MQTT 连接、IP、运行秒数；不展示密码 |
| HEARTBEAT | 原判活状态、最近心跳到达距今、90 秒阈值；未收到显示 NOT RECEIVED |
| SENSOR | 最近尝试成功/失败、距尝试和最后成功时间；未读显示 NOT READ / LAST GOOD -- |
| FAILSAFE | 未武装/已武装/已触发、健康联系、距最后联系、原 300 秒阈值；未武装显示 NO CONTACT |
| BOOT/FW | RTC 启动次数、复位原因、git 哈希、构建日期时间；次数不是生命周期累计 |

传感器时间记录在读取返回时；失败不把旧温湿度冒充有效新值，概览未读显示 WAIT DHT11，失败才显示 CHECK SENSOR。距今以每秒更新快照为准，不是墙钟；无符号差处理一次毫秒回绕，约 49.7 天未更新后无法区分更久的年龄。
